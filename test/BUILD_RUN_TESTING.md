# Проверка Build/Run на Sprinter

Адреса ниже взяты из текущего `Build/KodeEXE.LST`. После изменения исходников
нужно сначала пересобрать Kode и заново сверить листинг.

## Подготовка образа

```sh
./run/make.sh
./run/create_floppy_image.sh
mmd -i build/kode.img ::/PROJECT
mcopy -i build/kode.img -o test/buildtest.asm ::/PROJECT/MAIN.ASM
mcopy -i build/kode.img -o test/data/bld_bat/BUILD.BAT ::/PROJECT/BUILD.BAT
```

Запустить Kode с файлом из подкаталога, например:

```text
B:\KODE.EXE B:\PROJECT\MAIN.ASM
```

Подставить фактическую букву диска, если это не `B:`. Проверка из подкаталога
обязательна: именно она задействует исправленные `Dss.ChDir (#1D)` и
`Dss.Exec (#40)` с временным переключением `SLOT3`.

## Успешная сборка, exit code 0

1. Открыть в редакторе `B:\PROJECT\MAIN.ASM` и нажать F9.
2. До первой строки BUILD.BAT должна восстановиться консоль, сохранённая при
   открытии Kode. Рамок редактора под выводом быть не должно. Следующая сборка
   продолжает предыдущий вывод с сохранённой позиции курсора.
3. После успешного завершения не должно быть строки `Exit code 0` и ожидания
   клавиши. Возврат в Kode должен произойти сразу.
4. Меню, status line, все окна и текст должны появиться сразу. На чёрном экране
   не должна оставаться только надпись `rus`.
5. Проверить ввод текста, перемещение курсора и мышь. Повторить F9 три раза.
6. Выполнить `Run` (Ctrl+F9) с `RUN.BAT`: для кода 0 поведение должно быть тем
   же — сохранённая консоль и автоматический возврат с полным экраном Kode.

## Ошибка, exit code != 0

Для проверки выбрать проект без BUILD.BAT, с MAKEFILE и целью по умолчанию,
рецепт которой возвращает ненулевой код. Либо использовать тестовый MAKE.EXE,
возвращающий 7. Ожидание ошибки проверяется по коду, который возвращает дочерняя
программа непосредственно в DSS EXEC.

**Ограничение SYSTEM.EXE:** доступные исходники оболочки DSS завершают обработку
BAT с кодом 0, включая ошибку внутренней команды. Поэтому несуществующая команда
в BUILD.BAT не гарантирует строку `Exit code N` и ожидание клавиши в Kode.
Вывод ошибки остаётся в Show log. Для надёжного ненулевого результата BAT нужна
оболочка, передающая статус команд наружу; это отдельное изменение SYSTEM.EXE.
Проверенный источник: `sprinter_dss/utils/SYSTEM/SYS.ASM`, строки 81–84,
129–161 и 1557–1564. Этот внешний репозиторий не изменялся.

1. Нажать F9.
2. В конце должна появиться строка `Exit code N - press any key`, где `N != 0`.
3. До нажатия клавиши консоль должна оставаться видимой.
4. После клавиши Kode должен сразу восстановить весь экран и остаться рабочим;
   нажатая клавиша не должна повторно попасть в редактор.

Отдельно проверить каталог без BUILD.BAT и MAKEFILE: F9 должен показать
`No BUILD.BAT or MAKEFILE`, без reset и без повреждения экрана.

## Build → Target

В каталоге без MAKEFILE пункт Build → Target должен показать только
`No MAKEFILE`. Сообщение Build про BUILD.BAT здесь появляться не должно.

Для проверки возврата после MAKE.EXE:

1. Выбрать цель, которая запускает хотя бы одну команду рецепта, а не только
   печатает `Nothing to be done`.
2. После кода 0 Kode должен вернуться автоматически. `File` не должен быть
   выбран, ввод с клавиатуры и мышь должны работать сразу.
3. Повторить Target три раза, затем один раз F9. Все четыре запуска должны
   вернуться в один и тот же рабочий экран.
4. Target входит в общий хвост Build/Run переходом в
   `BrExec (#E46D)`; отдельного пути восстановления экрана у него больше нет.

## Сохранённая консоль

Сразу после открытия Kode доступен Build → Show console log. До первого
запуска там виден исходный экран консоли с баннером Kode, напечатанным от
текущей позиции курсора. После баннера курсор переходит на следующую строку.
Проверить первую и последнюю строки, цвета и курсор. Просмотр закрывается новым
нажатием любой клавиши или кнопки мыши; удерживаемая клавиша меню и её автоповтор не должны закрывать просмотр.
Завершающее событие и отпускание кнопки не должны попадать в редактор.

Проверить те же действия в DSS 40×32 и 80×32 на видеостраницах 0 и 1, с курсором
в середине экрана и у правой нижней границы. В 40×32 сохраняются 80 физических
колонок: BIOS использует два знакоместа на символ. Буфер содержит весь видимый экран,
без истории строк, уже ушедших за верхнюю границу.

После двух последовательных Build/Run/Target просмотр показывает продолжение
вывода. Строка ненулевого exit code включена в снимок. Отмена диалога Target,
отсутствие команды и ошибка загрузки сохраняют предыдущий снимок.

Перед просмотром и запуском выбрать второе окно, передвинуть курсор и выполнить
горизонтальную прокрутку. После возврата проверить окно, курсор, прокрутку и
ввод. Отмена выхода в диалоге сохранения должна оставлять редактор рабочим;
подтверждённый выход восстанавливает последний снимок, режим и курсор.

## Точки останова

Адреса относятся к текущей сборке; после пересборки сверить их в листинге.

| Операция | Адрес |
| --- | --- |
| Первоначальный снимок: InitialConsole.ConsoleGrab | #7D82 |
| Диспетчер: BldGo | #0BD9 |
| Движок: BldEntry | #E41C |
| Сохранение редактора: BldSaveEditor | #E848 |
| Вход в DOS: BldDosIn | #E6D4 |
| Общий запуск: BrExec | #E46D |
| Выполнение: BldExecCon | #E728 |
| Резидентный вызов DSS: BldDssTramp | #4F4C |
| Выход из DOS: BldDosOut | #E705 |
| Снимок консоли: ConsoleGrab | #E801 |
| Восстановление консоли: ConsoleRestore | #E824 |
| Ожидание нового нажатия: BldWaitKode | #E865 |
| Восстановление редактора: BldReInit | #E89A |
| Восстановление режима редактора: BldRestoreVM | #4FC2 |
| Восстановление консоли при выходе: BldConsoleExit | #0BFA |
| Безопасный вызов DSS: ConDss | #4F56 |
| Безопасное копирование BIOS: ConCopy | #4F7F |

Перед `Dss.Exec (#40)` строки в `BldCmdBuf (#ED2F)` и `ReCompBuff (#7B00)`
должны совпадать. Код завершения хранится в `BldErr (#E8D1)`.
Состояние снимка: `ConsoleReady (#E843)`, `ConsoleMode (#E844)`,
`ConsolePage (#E845)`, `ConsolePos (#E846)`. Номер физической страницы
буфера — `BldLogPg (#4FB5)`. Он входит в общий блок восьми страниц модулей.

Если появится reset или неполный экран, записать последнюю достигнутую точку,
код завершения, PC, SP и страницы SLOT0/SLOT2/SLOT3. Убедиться, что последним
действием восстановления консоли был `Dss.Locate (#52)`.

## Проверки на эмуляторе Z80

```sh
./run/make.sh
./run/create_floppy_image.sh
./test/run_tests.sh
node test/textio.js
node test/console.js
node test/buildrun.js
```

`test/console.js` исполняет собранные инструкции с постраничной памятью.
BIOS/DSS моделируются с изменением курсора, SLOT3 и регистров IX/IY.
Проверяется временный стек вне SLOT1, который BIOS переключает на видеопамять.
Проверяется полный загрузчик с настоящей распаковкой модулей, ошибки выделения
памяти и чтения, печать баннера от текущего курсора и его сохранение, оба
текстовых режима и страницы, последовательный вывод, Build/Run/Target, просмотр с клавиатурой и мышью,
сканирование PS/2 и восстановление при выходе. Графические функции редактора и
файловый поиск в тестах переходов заменены заглушками; отображение и реальную
работу BIOS/DSS дополнительно проверять в Sprinter/MAME.

## Автоматические проверки Sprinter/MAME

Сценарии рассчитаны на MAME 0.287, Sprinter BIOS v3.06, DSS system CHD размером 1 ГиБ
(4096×16×32, FAT16 начинается с LBA 63). Физический Sprinter не проверялся.
Скрипт подготовки читает исходный CHD и изменяет только копии в
`build/mame-console/`; ему нужны `sjasmplus`, `chdman` и `mtools`.
Копия содержит тестовый SYSTEM.BAT и небольшие EXE-родители Kode.

После канонической сборки выполнить из корня репозитория, подставив пути:

```sh
bash test/prepare_mame_console.sh /path/to/sp_hdd_sys.chd modes
mame sprinter -rompath /path/to/roms -hard1 build/mame-console/modes-system.chd \
  -bios v3.06 -video none -sound none -nothrottle -skip_gameinfo \
  -seconds_to_run 140 -autoboot_delay 0 -autoboot_script test/mame_console.lua \
  -snapshot_directory build/mame-console -nvram_directory build/mame-console \
  -diff_directory build/mame-console -cfg_directory build/mame-console
```

Ожидается `PASS: 4 real BIOS/DSS console transitions`. Каждый родитель заполняет
все строки цветным узором и устанавливает курсор в середине экрана (страница 0)
или справа внизу (страница 1). Родитель печатает баннер через DSS и сохраняет
эталон, затем возвращает исходный экран и курсор перед запуском Kode.
Lua открывает Show log, возвращает редактор и выходит. Родитель сравнивает
5120 байт символов/атрибутов с эталоном, режим, видеостраницу, конечный курсор
после баннера и код завершения.
Снимки `console-*-editor/show/return/exit.png` позволяют проверить отображение.

Для внешних запусков подготовить вариант `exec` той же командой и запустить
MAME с `-hard1 build/mame-console/exec-system.chd`,
`-autoboot_script test/mame_console_exec.lua` и `-seconds_to_run 70`.
Два Build печатают `BUILD_PASS`, Run печатает `RUN_PASS`, тестовый MAKE.EXE
печатает `TARGET_PASS` и возвращает 7. Проверка ищет все маркеры и сообщение
об ошибке в консоли после выхода; снимки `exec-*.png` показывают переходы.
Ожидается `PASS: two Builds, Run, Target error, Show log and exit with real DSS.Exec`.
Проверка успешна только при наличии соответствующего `PASS`, без `FAIL`;
один лишь код завершения MAME не подтверждает результат Lua-проверки.

## Окно Parameters

1. Открыть Run → Parameters сразу после загрузки файла: пустое поле должно быть
   полностью залито цветом InputLine, без фрагментов текста редактора.
2. Ввести строку, закрыть окно кнопкой OK, снова открыть его и проверить, что
   видны только сохранённые символы и чистый хвост поля. Начальная отрисовка
   выполняется в `PInpLine (#8C61)`.
3. Слева должна находиться кнопка OK, справа — Cancel; между кнопками должно
   быть два знакоместа.
4. После успешного Build меню должно оставаться неактивным; `File` не должен
   быть выбран. Снятие выбора выполняет `ResMBar (#0B1A)`.

## Аудит Build/Run: исправления и регрессии

В выборе команды сохраняется следующий порядок:

| Действие | Первый вариант | Если BAT отсутствует |
| --- | --- | --- |
| Build | `SYSTEM.EXE /C BUILD.BAT` | `MAKE.EXE` при наличии MAKEFILE |
| Run | `SYSTEM.EXE /C RUN.BAT <parameters>` | `MAKE.EXE run` при наличии явной цели run |
| Target | выбранная цель MAKEFILE | `MAKE.EXE <target>` |

Параметры сессии относятся только к RUN.BAT; они не добавляются к MAKE.EXE.
Предел — 64 символа. Каталог проекта берётся из полного имени активного файла,
до 127 символов, включая путь и имя. Для безымянного файла используется текущий
каталог DSS. SYSTEM.EXE и MAKE.EXE должны находиться через обычный поиск DSS.

Исправлены следующие ошибки:

- Файловые проверки и чтение MAKEFILE выполнялись напрямую из переключаемой
  страницы. Теперь аргументы открытия находятся в резидентной памяти, а
  возврат каждого DSS-вызова восстанавливает страницу кода.
- Ошибка чтения интерпретировалась как успешное чтение с неопределённой длиной;
  это приводило к чтению посторонней памяти или зависанию. Ошибки открытия,
  чтения и закрытия теперь останавливают запуск с сообщением `File I/O error`.
  Только отсутствие файла разрешает переход к следующему варианту команды.
- Ошибка перехода в каталог проекта раньше игнорировалась: запуск мог пойти
  из другого каталога. Теперь он отменяется. Ошибка восстановления исходного
  каталога также показывается после восстановления редактора.
- В буфере параметров не хватало байта для завершающего NUL при длине 64;
  повреждалось начало имени BUILD.BAT. Размер исправлен.
- Чтение нового блока MAKEFILE портило счётчик длины имени цели. Счётчик
  сохраняется, имена ограничены 24 символами, список не выходит за 256 байт.
  Некорректный индекс выбранной цели больше не вызывает бесконечный поиск.
- `run :` и `run\t:` распознаются; `run:=value` считается переменной.
  Проверены CR, LF, CRLF, EOF без перевода строки и переход через 512 байт.
- После отмены/ошибки сохранения сборка больше не продолжается со старым файлом.
  Общее сохранение прекращается при первой неудаче и возвращает исходное окно.

Список Target остаётся простым сканером явных целей: имена до 24 символов,
без пробелов, расширения переменных и шаблонов. Строки рецептов с начальным
пробелом/TAB, комментарии и специальные цели с начальной точкой пропускаются.
Динамические имена с `$`, шаблоны с `%` и имена, начинающиеся с `-`, не предлагаются
для запуска. Разбор зависимостей и исполнение рецептов остаются задачей MAKE.EXE.

Для размещения исправлений временный буфер чтения профилей/MAKEFILE совмещён
с буфером текста настроек. Эти операции выполняются последовательно; постоянные
профили и параметры не перекрываются. Ограничения размера страниц проверены сборкой.

`test/buildrun.js` добавляет 44 проверки настоящего собранного кода: поиск,
чтение, построение команды, DSS EXEC, возврат в редактор, выбор Target и цепочку
сохранения перед запуском. Модель DSS намеренно меняет SLOT3 и регистры, моделирует
ошибки и смену каталога дочерней программой. В этих проверках поиск команды и
чтение MAKEFILE не заменены заглушками. Графика и внешние программы моделируются.
Совместно с остальными наборами прошло 172 проверки (23 + 25 + 42 + 38 + 44).

Отображение и реальные SYSTEM.EXE/MAKE.EXE в Sprinter/MAME для этой ревизии
не проверены. Предыдущие попытки с локальными системными образами останавливались
до запуска Kode, на загрузке DSS; проход модели Z80 не заменяет эту проверку.
